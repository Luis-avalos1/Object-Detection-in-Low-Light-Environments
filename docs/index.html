Does image enhancement help detect objects in the dark?

A course project once concluded low-light enhancement gave “barely any improvement.” This rebuild shows that answer was right — but measured with a broken ruler. With a corrected COCO-style mAP evaluator, a fixed class taxonomy, and a sweep across six detector architectures, the honest picture emerges: on a frozen detector, classical enhancement is statistically neutral, and the real lever is adapting the detector itself.

The original result couldn’t be trusted

Not because the conclusion was wrong — because the measurement was.

The starting point was a student project on the ExDark low-light dataset (7,363 images, 12 classes). It reported one Precision/Recall/AP triple per enhancement method; they were all nearly identical, and the takeaway was “enhancement doesn’t help.”

The problem: the evaluation could not have shown a difference either way. Three independent flaws made the experiment uninterpretable.

Four bugs, four fixes

  • Metric. Averaged per-image precision[-1]/recall[-1] as “mAP” → PR curve collapsed. → pooled 101-pt COCO AP
  • False negatives invisible. Per-image AP ignored missed objects. → recall over total GT
  • Cup dropped. Missing from the class map → every Cup object discarded. → Cup→COCO 41
  • Boat mis-mapped to “traffic light” → Boat AP structurally ≈ 0. → Boat→COCO 8
Why this matters. The original conclusion (“enhancement barely helps”) happened to align with reality — but it was a guess dressed as a result. The contribution here is making that conclusion trustworthy, and then discovering what the broken metric hid.

A research-grade benchmark

One reproducible pipeline, runnable on any machine (CUDA → Apple MPS → CPU, auto-detected).

Correct evaluator. Pooled COCO-style mAP@0.5 & mAP@[.5:.95], per-class AP, bootstrap 95% CIs — cross-checked against Ultralytics val().
Six detectors. YOLOv5u, v8, v9, v10, YOLO11 (CNN, 4 generations) + RT-DETR (transformer) via one adapter.
12 enhancers. gamma / adaptive-gamma, brightness-contrast, HE, CLAHE (HSV & LAB), SSR/MSR/MSRCR, gray-world, dark-channel prior.
Deterministic. Seed-42, class-stratified 70/15/15 split committed so every experiment uses the identical partition.
Honest geometry. Ultralytics letterbox (no aspect-ratio squash); boxes mapped back to original pixels.
One command. python run.py runs the whole study and writes figures, CSVs, and a report.

CLAHE-LAB is the only method that beats doing nothing — by +0.003 mAP, which is inside the bootstrap confidence interval. Everything else is neutral-to-harmful. Aggressive global brightening (hist-eq, gray-world) pushes images away from the natural-photo distribution the COCO detector expects.

Take-away. The conclusion is robust precisely because it holds across different model types — it isn’t an artifact of one network. On a detector that never adapted to the enhanced domain, classical enhancement does not help.

Finding 2 — the per-class “wins” were noise

The interesting part: a single model looked like enhancement helped specific classes. It didn’t replicate.

On YOLOv8s alone, CLAHE-LAB appeared to boost several classes — Bottle +0.063, Cat +0.054, Dog +0.045. Tempting to call that a result.

But averaging each class’s change across all four detectors, only Motorbike improves consistently (positive on every model). Every other class is mixed — Bottle is +0.04, +0.06, −0.04, −0.07; Dog swings +0.05 to −0.11. That’s the fingerprint of sampling noise at 15 images/class, not a real effect.

The methodological point. A correct evaluator doesn’t just give you the right number — it lets you tell a real effect from a lucky one. Cross-checking a per-model finding against the other models is what turned a false positive into an honest null.

The decisive experiment (in progress)

Everything above tests a frozen detector — the setup where enhancement is expected to be neutral. The real question needs the detector to learn the enhanced domain.

Why frozen ≠ the real test

A COCO-pretrained detector has never seen CLAHE-processed pixels. Feeding it enhanced images is an out-of-distribution test. The literature shows enhancement pays off only when the detector is fine-tuned on the enhanced domain (e.g. Zero-DCE, MAET, PE-YOLO).

So the project ships a controlled A/B: fine-tune the same base on original vs enhanced images (identical epochs, split, seed — only the pixels differ), then evaluate a train-domain × test-domain matrix. The matched diagonal is the apples-to-apples answer.

Reproduce it in one command

Cross-platform (macOS / Windows / Linux). Device auto-detected. No CUDA required for the benchmark.

# 1. Environment
python -m venv venv
source venv/bin/activate      # Windows: venv\Scripts\activate
pip install -r requirements.txt

# 2. Run the whole study (detectors × enhancements → report + comparison)
python run.py                 # full benchmark
python run.py --quick         # ~80s smoke test
python run.py --full          # 6 detector families × all 12 enhancers

# 3. The decisive A/B on a GPU box: original-trained vs enhanced-trained
python run.py --stages domain report --domain --device auto \
  --domain-enhancers original clahe_lab --ft-epochs 100 --ft-fraction 1.0
  1. Correctness first. Known-answer unit tests pin the evaluator (IoU, AP, false-negative handling) and the enhancers before any model runs.
  2. Provenance built-in. Every metrics file records its device; --tag archives a per-machine snapshot so identical mAP across Mac/PC (differing only in FPS) is demonstrable.
  3. Self-documenting output. One run writes comparison.md, a heatmap, CSV/JSON matrices, and an HTML report — the figures on this page are generated, not hand-made.

Stack: Python · PyTorch · Ultralytics (YOLOv5/8/9/10/11, RT-DETR) · OpenCV · NumPy · scikit-learn · Matplotlib/Seaborn. Dataset: ExDark (Loh & Chan, 2019).
